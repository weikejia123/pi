## 一、版本概览

两个小版本（0.81.0 + 0.81.1），核心主题是 **Provider 生态开放 + Agent 可靠性加固**。

v0.81.0 完成了两个重要架构变化：SessionStorage 接口重构（breaking）和 provider 注册机制开放（extensions 可完整注册 provider）。v0.81.1 作为修复版本，主要加了 compaction 重试策略和 source archive 可验证发布。

## 三、技术深度评价

### 重要变更详解

#### 1. Compaction 弹性重试

**实现方式**：新增 `retryAssistantCall()` 方法，对瞬态 provider 失败使用已配置的重试策略（已有 retry/retry.ts），失败生命周期事件通过 `AgentHarness` 暴露。compaction 和 branch-summary 两条路径共用同一个机制。

**Tradeoff**：额外重试延迟 vs 提升长时间运行 agent 的鲁棒性。对于 `delegate_task` 子 agent 场景，每个 compaction 点都可能有 provider 调用，失败不重试可能丢失整个 session 的压缩成果。

**成熟度**：单 PR（#6901 by davidbrai），机制简洁，依赖现有的 retry 基础设施，非全新框架。

**WKJ 影响**：Hermes 大量使用 `delegate_task`（batch subagents），compaction 失败不再丢失进度。⭐⭐⭐⭐⭐

#### 2. Provider Extension 开放注册

**实现方式**：Extension 可以通过新的 API 注册完整 provider（含 auth、model refresh、filtering、streaming），不再需要修改 pi 源码来添加 provider。这是之前 `custom provider` 能力的超集。

**成熟度**：多 PR 实现（含 kimi-coding OAuth 认证作为参考实现），文档齐全。这是 pi 走向"插件化架构"的关键一步。

**WKJ 影响**：Hermes gateway 可以作为 pi 的一个 provider 注册，省去 gateway 转换层。⭐⭐⭐⭐

#### 3. SessionStorage 重构

**实现方式**：`getPathToRootOrCompaction()` 替代原有方法，compaction tails 作为自包含 checkpoint 存储。支持基于 cursor 的分页读取。本质上是将 compaction 从"线性追加"改为"checkpoint 式"。

**Tradeoff**：与之前存储不兼容，但向上提供了更清晰的抽象。

**WKJ 影响**：本地 wkj-dev 分支无 SessionStorage 层修改，merge 自动处理。⭐⭐

#### 4. llama.cpp 模型管理（重要澄清）

**首先要理解：llama.cpp 是推理后端，不是 pi 的功能——ollama 底层用的也是 llama.cpp 的推理代码。**

| 推理后端 | 管理方式 | 模型格式 | 典型显存占用 |
|---------|---------|---------|------------|
| **ollama**（用户当前在用） | `ollama pull/run`，pi 通过 `--model ollama/xxx` 连接 | GGUF 默认 FP16 精度 | qwen3.6:35b → ~23GB |
| **llama.cpp** | 启动 `llama-server`，pi 新增了通过 router 管理模型的能力 | GGUF 可量化（Q4/Q5/Q8） | 同样模型量化后→ ~12-20GB |

**v0.81.0 加的是什么？** pi 新增了"连接到 llama.cpp server 并管理其上的模型"的能力——搜索 HG、下载、加载/卸载、实时进度。**不是 pi 自己实现了更高效的推理引擎。**

**"省显存"的真相**：省显存的是 **GGUF 量化** 技术（Q4_K_M / Q5_K_M），不是 pi，也不是 llama.cpp 独有的。ollama 同样支持 GGUF 量化模型，只是默认不强制使用。你如果在 ollama 里跑 GGUF Q4 版本，效果一样。

**实现方式**：通过 HTTP 连接到 llama.cpp router，支持 `/login` 认证连接、`/llama` 搜索 HG 模型、下载进度、显式 load/unload。TUI 中显示实时进度。

**成熟度**：第一个版本，功能基础，后续可能扩展。

**WKJ 影响**：当前 qwen3.6:35b 在 ollama 下跑得好好的，完全不需要换。如果以后需要跑 72B/120B 级别模型，GGUF 量化有意义——但无论用 ollama 还是 llama.cpp 都能做量化，与 pi 的新功能无关。⭐⭐

### 整体评价

- **架构方向正确**：开放 provider 注册是 pi 从"内置 provider 集合"走向"provider 生态平台"的标志性版本
- **可靠性提升务实**：compaction 重试、cursor artifacts、paste 寄存器损坏都是长期存在的体验痛点
- **社区参与度**：davidbrai 3 PR、cristinaponcela 3 PR、xl0 2 PR、xz-dev 2 PR，社区贡献活跃
